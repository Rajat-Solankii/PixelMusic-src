## Why songs fail (verified live)
- ANDROID_VR `player`: LOGIN_REQUIRED "Sign in to confirm you're not a bot" from this IP, even with a visitor id.
- WEB_REMIX / TV / MWEB without `playbackContext.contentPlaybackContext.signatureTimestamp`: UNPLAYABLE
  "The page needs to be reloaded."
- With signatureTimestamp, WEB_REMIX (anonymous) is OK, but every audio format has only `signatureCipher` (`s`, `sp=sig`, `url`).
- Deciphered URL without `pot=`: the first ~1 MB plays (206), then 403. With `&pot=<token bound to the VIDEO ID>`: 206 everywhere.
  A token bound to the visitor id did NOT work.

## Verified recipe
1. Player script: GET `https://music.youtube.com/` (web UA). `"jsUrl":"/s/player/<id>/player_es6.vflset/en_GB/base.js"`;
   fetch it from `https://music.youtube.com` + jsUrl. `signatureTimestamp:(\d+)` in base.js (20760 for player a5c2aafe).
2. Patch base.js: replace the first `var window=this;` with `var window=globalThis;`, find the decipher function with
   `[;,\n]([A-Za-z0-9_$]+)=function\([\w$]+,[\w$]+="",[\w$]+=""\)\{[\w$]+=new g\.[\w$]+\([\w$]+,!0\);[\w$]+\.set\("alr","yes"\)`
   (name `Bs` in a5c2aafe; its signature is `(url, sp="", s="")`), and insert `;g.__mf_bs=<name>;` before the last `})(_yt_player);`.
3. Evaluate env.js (with `globalThis.__DOM_SURFACE = <dom_surface.json>` first) + the patched base.js in an rquickjs
   Context (~1.2 s in release). Final URL = `__str(_yt_player.__mf_bs(url, sp, s))`, where `__str(r)` calls the URL
   object's zero-arg prototype method that returns a string starting with `http` (skip `constructor`/`clone`). This
   deciphers `s` and transforms `n`; call it with `("", "")` for formats that already have a plain `url` (n still transforms).
4. BotGuard: POST `https://www.youtube.com/api/jnn/v1/Create` body `["O43z0dpjhgX20SCx4KAo"]`, headers
   `content-type: application/json+protobuf`, `x-goog-api-key: REDACTED_API_KEY`,
   `x-user-agent: grpc-web-javascript/0.1`, web UA. In a fresh Context: set `__realms` (an array with the globals of 4 other
   Contexts in the same Runtime, via `rquickjs::Persistent`) and optionally `__hostNow` (ms as f64 from an Instant), eval
   `__DOM_SURFACE` + env.js + botguard.js, then `__start(<create response>)`. Pump: run pending jobs, check
   `__error || (__bgResponse ? 'ok' : '')`, eval `__tick()`, sleep 1 ms (snapshot takes ~250 ms). Then POST `.../GenerateIT`
   body `["O43z0dpjhgX20SCx4KAo","<__bgResponse>"]` and get `[integrityToken, ttlSecs(43200), refresh, fallback]`.
   `integrityToken == null` means BotGuard rejected the environment. Then `__integrity(<it response>)`, pump until `__minter`,
   `__mint("<videoId>")`, pump until `__token` (base64url, ~116 chars). One minter serves every video until ttl (minus 10 min).
5. Player request: WEB_REMIX `player`, `Login::IfSignedIn`, body
   `{videoId, playbackContext:{contentPlaybackContext:{signatureTimestamp}}, serviceIntegrityDimensions:{poToken}}`;
   stream URL = deciphered URL + `&pot=<token>`; stream `user_agent` = the WEB UA. Not yet verified: whether the
   video-bound token also works when signed in (test in the app).
Scratch probes that proved all of this: shared notes folder `po-token-probes/` (rquickjs 0.9 `bg.rs`, `main.rs`, `assemble.py`).

## Remaining steps
1. Dependency: `rquickjs = "0.9"` (default features; it builds quickjs-ng with cc on MSVC, ~30 s) in the root
   `[workspace.dependencies]` and in `crates/sf-services/Cargo.toml`. Consider
   `[profile.dev.package.rquickjs-sys] opt-level = 2` so debug builds don't run base.js at -O0.
2. `youtube/jsworker.rs`: one dedicated thread (16 MB stack) owning `rquickjs::Runtime` (memory limit ~256 MB,
   `set_max_stack_size` 8 MB, interrupt handler with a per-job deadline) and named Contexts. Async API: `run(job)`
   sends a `FnOnce(&mut Engine) -> R` and awaits a tokio oneshot; spawn lazily; respawn if the thread died.
   Helpers: fresh context (with realms + `__hostNow`), eval to String with the exception message on error, pump_until(check, timeout).
3. `youtube/cipher.rs`: `player_path(page)`, `signature_timestamp(js)`, `prepare(js)` (pure, unit-tested on a synthetic
   base.js), and `Cipher { worker, state }` that loads the script lazily, keeps it ~6 h, reloads on failure, and has
   `decipher(url, sp, s)`. JS helper `__mfDecipher(url, sp, s)` wraps `__str`.
4. `youtube/potoken.rs`: `PoTokens` with a per-video token cache (until minter expiry), the built-in BotGuard minter
   (step 4 above), and an optional external bgutil-style provider: POST `{server}/get_pot` with `{"content_binding": id}`,
   reply `{"poToken": ...}`. Set it with `YouTubeService::set_po_token_server(Option<String>)` and the env var
   `MATERIALFY_POT_PROVIDER`. No Settings UI (QML is being edited by another worker), so list that as a follow-up.
   `forget(video_id)` on 403 (`StreamSource::invalidate`).
5. `client.rs`: `get_text(path)` against `site_base` with the web UA; a BotGuard base URL (`https://www.youtube.com/api/jnn/v1/`)
   that `with_base_url` points at the mock (`{base}/api/jnn/v1/`).
6. `stream.rs`: replace the WEB_REMIX tier with the web tier above (anonymous or signed in). Order: ANDROID_VR (cheap when
   it works, rests 15 min after a bot check), then web. Generalize `parse_player` to also return the cipher (`s`, `sp`, url
   decoded) of the chosen audio/mp4 format; keep `parse_player`'s current behaviour for ANDROID_VR. Rest the web tier
   only after technical failures (decipher, BotGuard, HTTP), not after per-song refusals. Log at debug.
